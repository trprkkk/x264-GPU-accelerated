# Phase 6: CUDA for Kepler..Volta (CUDA 11.8 kernels + driver API) (2026-11-15)

Supersedes `multiarch-fallback.txt` (which had Kepler..Volta on OpenCL only).

## Why

pre-Turing GeForce cards were left to the OpenCL backend because CUDA Toolkit
13 cannot compile for them and its runtime refuses to initialise on the older
drivers those GPUs are stuck with (Kepler's last driver is R470).  CUDA 11.8
is the last toolkit that covers Kepler..Hopper and its runtime works on every
driver from R451 up, so the backend now uses two toolkits' kernel images and
loads them through the CUDA driver API.

## What was built

* **Kernel/host split.**  `common/gpu_kernels.cu` contains the kernels only and
  is compiled with `nvcc -fatbin`; `common/gpu_cuda.cpp` is the host side and
  is compiled by the regular C++ compiler.  This was mandatory: the VS 18
  standard library refuses to be parsed by CUDA front ends older than 13.2
  ("error STL1002"), and the host side must not go through nvcc 11.8 at all.
* **Minimal stub header.**  `common/cuda_stub/cuda_runtime.h` is placed in
  front of the CUDA include path for the kernel build, so only the
  device-side declarations (crt/host_defines.h, device_launch_parameters.h)
  are used; the kernels provide their own min/max.
* **Two kernel images, loaded at runtime.**  CUDA 11.8 builds sm_35..sm_90 +
  compute_75 PTX; CUDA 13.x builds sm_100/sm_120 + compute_90 PTX.  Both are
  embedded as RCDATA resources (`gpu_res.o`) and loaded with
  `cuModuleLoadData` from a dynamically loaded `nvcuda.dll`.  The device's
  compute capability picks the image; the other one is tried as a fallback.
  `X264_GPU_FATBIN=legacy|modern` forces one for testing.
* **Host API stays cudart.**  Memory, streams, copies and events use cudart
  11.8 (statically linked, minor-version-compatible with R451+ drivers);
  only module loading and kernel launches go through the driver API.
* **Context fix.**  cudart 11.8 can leave a *destroyed* handle current after
  its device queries (`CUDA_ERROR_CONTEXT_IS_DESTROYED` from
  `cuModuleLoadData`); the backend now retains the primary context explicitly
  and makes it current instead of trusting `cuCtxGetCurrent`.
* **Staging ring.**  Reference uploads now alternate between two pinned
  staging buffers fenced with events: the previous single buffer could be
  overwritten while its async copy was still reading it, which becomes
  reachable on old (slow PCIe) machines where the copy can outlast the CPU
  staging.
* Build scripts: `configure-msvc.sh` writes `NVCC_LEGACY`/`NVCC_MODERN`,
  `CUDAFLAGS_LEGACY`/`CUDAFLAGS_MODERN`; `make-msvc.sh` appends the CUDA
  include directory to INCLUDE (appending keeps the toolkit's own stdint.h
  from shadowing the compiler's).

## Notes

* CUDA 11.8's ptxas produces the sm_35..sm_90 images; sm_100/sm_120 stay with
  the modern toolkit so Blackwell keeps native code (no JIT).
* Kepler..Volta execution could not be tested on real hardware here; the
  kernels are the same source that is verified bit-exact on sm_75, and the
  OpenCL backend remains as a fallback if a driver rejects the image.
* The build now requires both toolkits (11.8 and a 12.8+/13.x), see README.
